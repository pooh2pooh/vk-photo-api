# VK Saved Photos

Веб-интерфейс для фотографий из альбома «Сохранённые фото» ВКонтакте.
TypeScript + React. Работает из **любой поддиректории** Apache, защищён логином/паролем,
токен VK и учётные данные не попадают в браузер.

## Возможности

- 🔐 **Авторизация**: вход по логину/паролю, галерея не открывается без входа (HTTP-only cookie-сессия).
- 🗝 **Секреты на сервере**: токен VK и пароль хранятся в `private/secrets.php`
  (закрыт `.htaccess`), браузеру не передаются. `config.js` больше не нужен.
- ⚡ **Кэширование**: страницы кэшируются на сервере (`private/cache/`, 5 минут) и в
  браузере (localStorage + кэш картинок) — повторные просмотры мгновенные.
- 🖼 **Гибкая сетка**: фото выстраиваются «паззлом» и заполняют свободное пространство
  независимо от ориентации. Кнопка **«Обзор»** в шапке мгновенно переключает
  режим: 100 фото на странице с превью примерно вдвое мельче (пагинация
  пересчитывается на лету, выбор запоминается в localStorage). Страница в 100 фото
  укладывается ровно в один запрос к VK — это безопасно для частотного лимита.
- 🚀 **UX**: экран входа, лоадеры, `cursor: progress`, плавные появления; в лайтбоксе —
  спиннер до загрузки фото, предзагрузка соседних кадров, лента миниатюр снизу и
  навигация стрелками / колесом мыши (с защитой от слишком частого листания).
  Лента — единый трек: число миниатюр постоянно, активная всегда по центру,
  движение плавное, а крайние миниатюры «затухают», создавая эффект бесконечности.
- 🛡 **Отказоустойчивая загрузка**: бандл не «виснет» в Яндекс.Браузере — загрузчик
  берёт его из localStorage, затем из CDN-зеркала (jsDelivr, один запрос по HTTP/2),
  затем через `api.php?action=asset` (gzip), статику, Range-куски и `fetch`+инлайн;
  плюс терминальный лог, маячок диагностики и заглушка — «вечной загрузки» не бывает.
- 🎨 **Иконки**: полный набор favicon/иконок (SVG + PNG + ICO + manifest) генерируется скриптом.

## Требования

- Apache с **PHP >= 8.0** (или любой PHP-хостинг; локально — `php -S`)
- Персональный **user-токен** ВКонтакте, scope `photos` (токен сообщества не подойдёт)

## Как запустить в /var/www/html

```bash
# 1. собери фронтенд (нужен Node) или возьми готовую сборку из корня репозитория
npm ci
npm run build

# 2. скопируй содержимое репозитория в любую поддиректорию
cp -r vk-photo-api /var/www/html/vkphotos

# 3. настрой секреты
cd /var/www/html/vkphotos
cp private/secrets.example.php private/secrets.php
php scripts/make-hash.php 'твой-пароль'   # выдаст хэш — вставь в secrets.php
```

Заполни `private/secrets.php`:

```php
return [
    'username'      => 'admin',
    'password_hash' => '$2y$12$...результат-make-hash...',
    'vk_token'      => 'ВАШ_USER_ТОКЕН_VK',
];
```

Открой `http://host/vkphotos/` и войди.

> `.htaccess` внутри `private/` запрещает прямой доступ к папке (Apache 2.4:
> директива `Require all denied`). Нужен `AllowOverride All` для каталога с сайтом,
> иначе файлы `private/` будут отдаваться Apache. В идеале место размещения
> приватных данных вынеси за пределы webroot.

Корневой `.htaccess` (кладётся вместе с сайтом) отключает сжатие и трансформацию
ответов для `.js`/`.css` (`no-transform`, `no-gzip`, `no-brotli`). Это лечит
случаи, когда большие скрипты «зависают» при загрузке в Яндекс.Браузере из-за
сжатия или прокси режима «Турбо». Для его работы тоже нужен `AllowOverride All`.

## Получение user-токена VK

Альбом «Сохранённые фото» — личный, поэтому нужен именно user-токен:

1. https://vk.com/editapp?act=create → тип «Standalone-приложение», скопируй `App ID`.
2. Открой (без пробелов в URL!):

   ```
   https://oauth.vk.com/authorize?client_id=ВАШ_APP_ID&display=page&redirect_uri=https%3A%2F%2Foauth.vk.com%2Fblank.html&scope=photos,offline&response_type=token&v=5.199
   ```

3. «Разрешить» → в адресной строке после `…#` скопируй `access_token=…`.
4. Вставь в `private/secrets.php` → `vk_token`. Право `offline` = бессрочный.

## Отказоустойчивая загрузка интерфейса

Основной бандл собирается в **классический IIFE**, но в `index.html` тегом
`<script src>` **не прописывается** — загрузчик подключает его сам. Такой
подвисший тег не блокирует событие `load` и вкладку. Цепочка источников JS:

1. **PHP-ассет `api.php?action=asset&f=app-<hash>.js`** — gzip, точный
   `Content-Length`, `no-transform`, ETag/304; в Яндекс.Браузере прямой запрос
   к `assets/*.js` может «зависать» вечно, а маленький PHP-ответ отдаётся;
2. **статический `./assets/app-<hash>.js`**;
3. **копия из localStorage** (с прошлого захода, инлайн-инъекцией);
4. **CDN-зеркала** из `shell-config.js` и те же зеркала через прокси;
5. **`fetch` + инлайн-инъекция** с таймаутом чтения тела (последний резерв).

Резервный перебор начинается с **копии из localStorage** (мгновенно), затем
идут **CDN-зеркала** (включая зеркала через прокси), и лишь потом — статический
`./assets/*.js`: на «медленном» хостинге статика как раз и подвисает.

**Яндекс.Браузер** (определяется по UA) не грузит целые ответы с хостинга: HTTP
200 приходит, а байты тела — нет (0 байт за 24 c). Поэтому его цепочка быстрого
запуска такая:

1. **localStorage** — повторные заходы мгновенны (0 запросов);
2. **CDN-зеркало** — один запрос по HTTP/2 (jsDelivr) вместо десятков кусков;
3. **Range-куски** по ~8 КБ с PHP-ассета, затем со статики (`206`,
   `Content-Range`, raw-байты, без gzip) — резерв, когда зеркал нет/недоступны.

Range-куски могут «застревать» (таймаут `rangeTimeoutMs`): зависший кусок
откладывается в конец очереди (`rangeRetries` попыток) **не блокируя
остальные** — пул (`rangePool`) берёт следующий, поэтому один зависший запрос
не роняет и не тормозит загрузку. Вдобавок к каждому куску при отсутствии
ответа за `rangeHedgeMs` посылается **дубль на другом соединении** (hedged
request) — побеждает первый пришедший. Сторож (`readyWatchdogMs`) срабатывает,
только если **вообще нет прогресса** 20 с (каждый докачанный кусок сбрасывает
окно). Собранный бандл сразу кладётся в **localStorage**. Range-режим
используется и как последний резерв в обычных браузерах (если тело ответа
«зависло»).

CSS подключается статическим `<link rel="stylesheet">`, при его сбое — ассет
через PHP и localStorage. Стили по-прежнему лежат в `assets/`.

Рядом работает загрузчик (`web/shell-runtime.js`, встраивается в HTML на этапе
`build:shell`):

1. держит **единственный постоянный оверлей** со спиннером (без перерисовки),
   плавно (CSS `opacity`/`visibility`) скрывает его при готовности;
2. ведёт **цветной терминальный лог** с таймингами: жизненный цикл загрузчика,
   источники, JS-ошибки, запросы/ответы приложения. Лог доступен приложению
   через `window.__VK_LOADER__` (`net/ok/warn/error/info`), а пользователю —
   кнопкой «лог» в правом нижнем углу после запуска;
3. ждёт готовности приложения по флагу `window.__APP_READY__`
   (а не по событию `load` у скрипта — некоторые движки его не присылают);
4. если бандл так и не запустился за `readyWatchdogMs`, показывает заглушку
   с кнопкой **«Повторить»** — она сразу очищает лог, показывает оверлей со
   спиннером и перезапускает загрузку;
5. шлёт **маячок диагностики** (`action=diag`): User-Agent, лог и Resource
   Timing уходят на сервер в `private/diag/` при успехе и при сбое — по ним
   видно, что происходит в Яндекс.Браузере, без DevTools на клиенте.

> `earlyFallbackMs`/`jsInline` более не используются (детектор тихой блокировки
> и инлайн-бандл заменены моделью «загрузчик сам грузит основной источник»),
> оставлены только для совместимости старых конфигов.

> Ошибка `shell-config.js` не считается сбоем основного ресурса и резерв
> не запускает — зеркала просто остаются пустыми.

### CDN-зеркала (подставляются автоматически)

`scripts/build-shell.mjs` при сборке определяет GitHub-репозиторий из
`git remote get-url origin` (или переменной окружения `MIRROR_REPO=логин/репо`)
и **сам прописывает** jsDelivr-зеркала в `shell-config.js` для текущего бандла
(два хоста — `cdn.jsdelivr.net` и `fastly.jsdelivr.net`):

```
https://cdn.jsdelivr.net/gh/ЛОГИН/РЕПО@main/assets/app-<hash>.js
```

Чтобы зеркало заработало, файлы `assets/app-<hash>.js|css` должны быть
**запушены в публичный репозиторий** (`git push`). Имя с `<hash>` делает кэш
CDN безопасным: новая сборка — новое имя. Если репозиторий приватный или файл
не запушен, jsDelivr вернёт 404, загрузчик молча уйдёт на Range-куски.

Автоматику можно отключить (`MIRROR_REPO=` пустой и без git remote) или
дополнить URL-ы руками прямо в `shell-config.js` (GitHub Pages, Cloudflare
Pages, Netlify и т.п.) — загрузчик переберёт их по очереди, а если прямой
доступ к CDN заблокирован — через предзаполненные CORS-прокси.

> При новой сборке имена файлов меняются (`<hash>`) — после `git push` зеркала
> подставятся на следующей сборке; при ручной правке обнови URL в `shell-config.js`.

## API

Все запросы идут на `./api.php` (относительный путь — работает в любой поддиректории).

| Действие | Метод | Описание |
| -------- | ----- | -------- |
| `session` | GET | Текущее состояние (authorized, setupRequired) |
| `login` | POST | Вход: `{username, password}` |
| `logout` | GET | Выход |
| `photos` | GET | `offset`, `count` (1…1000) — страница фотографий (только после входа) |
| `stacks` | GET | `refresh=1` — пересобрать/получить «стопки» похожих фото (ИИ; долго при первом запуске) |
| `stack_photos` | GET | `gid` — фото конкретной стопки |
| `asset` | GET | `f=app-<hash>.js\|css` — ассет в gzip (`no-transform`, ETag/304) или Range-кусками (`206`, raw-байты) |
| `diag` | POST | Маячок диагностики загрузчика (лог + Resource Timing → `private/diag/`) |

Формат ошибок: `{"error": {"code": "...", "message": "...", "details": null}}`.

Ответы `photos` тоже отдаются в gzip с явным `Content-Length`: в Яндекс.Браузере
большие тела без него приходят пустыми (тело 0 байт → «долгая загрузка», затем
ошибка разбора). Поэтому, если страница превышает `PAGE_CHUNK_SIZE` (100), она
запрашивается порциями — каждая порция сжимается до ~1–2 КБ, кэшируется на
сервере и в localStorage, а фото показываются по мере загрузки. Если отдельная
порция не пришла, показывается уже загруженное (без общей ошибки).

Прокси ходит в VK со стороны сервера (`photos.get`, API `v=5.199`) и кэширует
ответы на 5 минут. Коды ошибок VK (`5`, `6`, `9`, `14`, `15`, `27`, `29`, `100`,
`200`, `1117`, `3610`) переводятся в понятные сообщения; на лимиты `6/9/29` и
сетевые сбои запрос повторяется с паузой. `VK_27` означает, что в `secrets.php`
положен токен сообщества вместо user-токена.

### Лимиты VK API

### «Стопки» похожих фото (ИИ)

Кнопка «Стопки» в шапке группирует все сохранённые фото на похожие темы:
сервер скачивает миниатюры, пакетами отправляет их в ИИ-модель (просит короткую
тему каждого кадра), а затем локально склеивает похожие темы в стопки. Клик по
стопке показывает только её фото; «Ко всем фото» возвращает общий список.

Модель выбирается свободно из каталога [freellm.net](https://freellm.net/) —
подходит любая OpenAI-совместимая vision-модель. По умолчанию — бесплатная
**Gemini** (Google AI Studio, без карты). Настройка в `private/secrets.php`:

```php
'ai_api_key'  => '…',   // ключ провайдера
'ai_base_url' => 'https://generativelanguage.googleapis.com/v1beta/openai',
'ai_model'    => 'gemini-2.5-flash', // пример; сверяй актуальный id на freellm.net
```

(или переменные окружения `VK_PHOTO_AI_KEY` / `VK_PHOTO_AI_BASE_URL` /
`VK_PHOTO_AI_MODEL`). Результат кэшируется на 12 часов в
`private/ai-cache/`; кнопка «Пересобрать» (`refresh=1`) запускает обновление.
Без ключа кнопка честно сообщит, что ИИ не настроен. Первый запуск может занять
минуты (1000 фото ≈ 63 пакета по 16 изображений) — последующие мгновенные.

По [официальной документации](https://dev.vk.com/ru/api/api-requests) методы с
**user-токеном** (кроме секций `secure`/`ads`) вызываются **не чаще 3 раз в
секунду** (сообщества — 20/с; сервисные — 5–60/с в зависимости от числа
пользователей). При превышении VK отвечает ошибкой `6` («Too many requests per
second»), а за частые однотипные вызовы — `9` (flood) и `29` (rate limit).

Чтобы не упереться в лимит, бэкенд держит глобальный интервал ≈340 мс между
любыми вызовами VK (файл-замок `private/cache/vk-throttle.lock`), поэтому даже
параллельные запросы (несколько вкладок, быстрая пагинация) идут в VK
последовательно. Плюс страница «Обзор» = 100 фото = ровно один вызов, а ответы
кэшируются на 5 минут.

## Локальная разработка

```bash
npm install
npm run dev:php     # терминал 1: api.php на http://localhost:8090
npm run dev         # терминал 2: Vite на http://localhost:5173 (проксирует /api.php)
```

Для боевого `/api` в dev-режиме создай `private/secrets.php` с реальными значениями.

## Структура

```
api.php                         # бэкенд: логин + прокси VK + кэш + asset/diag
index.html                      # собранный отказоустойчивый загрузчик (после build:shell)
shell-config.js                 # CDN-зеркала (jsDelivr) и прокси; подставляются на сборке
assets/                         # собранный JS/CSS
icon.svg / favicon.ico / …      # иконки и site.webmanifest (после build:icons)
private/                        # секреты (закрыты .htaccess):
│  ├─ secrets.example.php       #   шаблон конфигурации
│  ├─ secrets.php               #   ТВОИ логин/пароль/токен (создать, не коммитить)
│  ├─ cache/                    #   серверный кэш ответов VK
│  ├─ asset-cache/              #   gzip-копии ассетов для api.php?action=asset
│  └─ diag/                     #   маячки диагностики загрузчика
scripts/make-hash.php           # генерация хэша пароля
scripts/make-icons.sh           # генерация иконок (rsvg-convert + ImageMagick)
web/                            # React + Vite (исходники)
│  ├─ src/api/                  # client (api.php), config (pageSize)
│  ├─ src/components/           # Login, Gallery, PhotoCard, Pagination, Lightbox
│  ├─ src/hooks/usePhotos.ts    # пагинация + кэш localStorage
│  ├─ icons/icon.svg            # исходная SVG-иконка «В»
│  ├─ shell-runtime.js          # загрузчик ресурсов (встраивается в index.html)
│  └─ shell-config.js           # шаблон зеркал/прокси (jsDelivr подставляется на сборке)
server/                         # опциональный Node-бэкенд (для будущих этапов ИИ)
```

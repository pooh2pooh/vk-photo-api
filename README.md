# VK Saved Photos

Веб-интерфейс для фотографий из альбома «Сохранённые фото» ВКонтакте.
TypeScript + React. Работает из **любой поддиректории** Apache, защищён логином/паролем,
токен VK и учётные данные не попадают в браузер.

## Возможности

- 🔐 **Авторизация**: вход по логину/паролю, галерея не открывается без входа (HTTP-only cookie-сессия).
- 🗝 **Секреты на сервере**: токен VK и пароль хранятся в `private/secrets.php`
  (закрыт `.htaccess`), браузеру не передаются. `config.js` больше не нужен.
- ⚡ **Кэширование**: страницы кэшируются на сервере (`private/cache/`, 5 минут) и в
  браузере (localStorage + кэш картинок) — повторные просмотры мгновенные.
- 🖼 **Гибкая сетка**: фото выстраиваются «паззлом» и заполняют свободное пространство
  независимо от ориентации.
- 🚀 **UX**: экран входа, лоадеры, `cursor: progress`, плавные появления, lightbox.
- 🛡 **Отказоустойчивая загрузка**: бандл не «виснет» в Яндекс.Браузере — загрузчик
  сам подгружает его через `api.php?action=asset` (gzip), затем статику `assets/*.js`,
  копию из localStorage, CDN-зеркала и через `fetch`+инлайн; плюс терминальный лог,
  маячок диагностики и заглушка — «вечной загрузки» не бывает.
- 🎨 **Иконки**: полный набор favicon/иконок (SVG + PNG + ICO + manifest) генерируется скриптом.

## Требования

- Apache с **PHP >= 8.0** (или любой PHP-хостинг; локально — `php -S`)
- Персональный **user-токен** ВКонтакте, scope `photos` (токен сообщества не подойдёт)

## Как запустить в /var/www/html

```bash
# 1. собери фронтенд (нужен Node) или возьми готовую сборку из корня репозитория
npm ci
npm run build

# 2. скопируй содержимое репозитория в любую поддиректорию
cp -r vk-photo-api /var/www/html/vkphotos

# 3. настрой секреты
cd /var/www/html/vkphotos
cp private/secrets.example.php private/secrets.php
php scripts/make-hash.php 'твой-пароль'   # выдаст хэш — вставь в secrets.php
```

Заполни `private/secrets.php`:

```php
return [
    'username'      => 'admin',
    'password_hash' => '$2y$12$...результат-make-hash...',
    'vk_token'      => 'ВАШ_USER_ТОКЕН_VK',
];
```

Открой `http://host/vkphotos/` и войди.

> `.htaccess` внутри `private/` запрещает прямой доступ к папке (Apache 2.4:
> директива `Require all denied`). Нужен `AllowOverride All` для каталога с сайтом,
> иначе файлы `private/` будут отдаваться Apache. В идеале место размещения
> приватных данных вынеси за пределы webroot.

Корневой `.htaccess` (кладётся вместе с сайтом) отключает сжатие и трансформацию
ответов для `.js`/`.css` (`no-transform`, `no-gzip`, `no-brotli`). Это лечит
случаи, когда большие скрипты «зависают» при загрузке в Яндекс.Браузере из-за
сжатия или прокси режима «Турбо». Для его работы тоже нужен `AllowOverride All`.

## Получение user-токена VK

Альбом «Сохранённые фото» — личный, поэтому нужен именно user-токен:

1. https://vk.com/editapp?act=create → тип «Standalone-приложение», скопируй `App ID`.
2. Открой (без пробелов в URL!):

   ```
   https://oauth.vk.com/authorize?client_id=ВАШ_APP_ID&display=page&redirect_uri=https%3A%2F%2Foauth.vk.com%2Fblank.html&scope=photos,offline&response_type=token&v=5.199
   ```

3. «Разрешить» → в адресной строке после `…#` скопируй `access_token=…`.
4. Вставь в `private/secrets.php` → `vk_token`. Право `offline` = бессрочный.

## Отказоустойчивая загрузка интерфейса

Основной бандл собирается в **классический IIFE**, но в `index.html` тегом
`<script src>` **не прописывается** — загрузчик подключает его сам. Такой
подвисший тег не блокирует событие `load` и вкладку. Цепочка источников JS:

1. **`api.php?action=asset&f=app-<hash>.js`** — PHP отдаёт тот же файл в gzip
   с точным `Content-Length`, `no-transform`, ETag/304 (в Яндекс.Браузере прямой
   запрос к `assets/*.js` может «зависать» вечно, а PHP-ответ отдаётся);
2. **статический `./assets/app-<hash>.js`**;
3. **копия из localStorage** (с прошлого захода, инлайн-инъекцией);
4. **CDN-зеркала** из `shell-config.js` и те же зеркала через прокси;
5. **`fetch` + инлайн-инъекция** с таймаутом (последний резерв).

CSS подключается статическим `<link rel="stylesheet">`, при его сбое — ассет
через PHP и localStorage. Стили по-прежнему лежат в `assets/`.

Рядом работает загрузчик (`web/shell-runtime.js`, встраивается в HTML на этапе
`build:shell`):

1. держит **единственный постоянный оверлей** со спиннером (без перерисовки),
   плавно (CSS `opacity`/`visibility`) скрывает его при готовности;
2. ведёт **цветной терминальный лог** с таймингами: жизненный цикл загрузчика,
   источники, JS-ошибки, запросы/ответы приложения. Лог доступен приложению
   через `window.__VK_LOADER__` (`net/ok/warn/error/info`), а пользователю —
   кнопкой «лог» в правом нижнем углу после запуска;
3. ждёт готовности приложения по флагу `window.__APP_READY__`
   (а не по событию `load` у скрипта — некоторые движки его не присылают);
4. если бандл так и не запустился за `readyWatchdogMs`, показывает заглушку
   с кнопкой **«Повторить»** — она сразу очищает лог, показывает оверлей со
   спиннером и перезапускает загрузку;
5. шлёт **маячок диагностики** (`action=diag`): User-Agent, лог и Resource
   Timing уходят на сервер в `private/diag/` при успехе и при сбое — по ним
   видно, что происходит в Яндекс.Браузере, без DevTools на клиенте.

> `earlyFallbackMs`/`jsInline` более не используются (детектор тихой блокировки
> и инлайн-бандл заменены моделью «загрузчик сам грузит основной источник»),
> оставлены только для совместимости старых конфигов.

> Ошибка `shell-config.js` не считается сбоем основного ресурса и резерв
> не запускает — зеркала просто остаются пустыми.

### Как добавить зеркала (бесплатно)

1. Заведи публичный GitHub-репозиторий и положи в него папку `assets/`
   (файлы `app-<hash>.js` и `app-<hash>.css` из корня).
2. jsDelivr раздаёт любой GitHub-репозиторий без регистрации:

   ```
   https://cdn.jsdelivr.net/gh/ЛОГИН/РЕПО@main/assets/app-<hash>.js
   ```
3. Пропиши такие URL в `shell-config.js` (рядом с `index.html`) в массивы `js`/`css`.
   Зеркал можно несколько; прокси уже предзаполнены и перебираются автоматически.

> При новой сборке имена файлов меняются (`<hash>`) — обнови URL зеркал в `shell-config.js`.

## API

Все запросы идут на `./api.php` (относительный путь — работает в любой поддиректории).

| Действие | Метод | Описание |
| -------- | ----- | -------- |
| `session` | GET | Текущее состояние (authorized, setupRequired) |
| `login` | POST | Вход: `{username, password}` |
| `logout` | GET | Выход |
| `photos` | GET | `offset`, `count` — страница фотографий (только после входа) |
| `asset` | GET | `f=app-<hash>.js\|css` — тот же ассет в gzip, `no-transform`, ETag/304 |
| `diag` | POST | Маячок диагностики загрузчика (лог + Resource Timing → `private/diag/`) |

Формат ошибок: `{"error": {"code": "...", "message": "...", "details": null}}`.

Прокси ходит в VK со стороны сервера и кэширует ответы на 5 минут.
`VK_27` означает, что в `secrets.php` положен токен сообщества вместо user-токена.

## Локальная разработка

```bash
npm install
npm run dev:php     # терминал 1: api.php на http://localhost:8090
npm run dev         # терминал 2: Vite на http://localhost:5173 (проксирует /api.php)
```

Для боевого `/api` в dev-режиме создай `private/secrets.php` с реальными значениями.

## Структура

```
api.php                         # бэкенд: логин + прокси VK + кэш + asset/diag
index.html                      # собранный отказоустойчивый загрузчик (после build:shell)
shell-config.js                 # список CDN-зеркал и прокси (правится на сервере)
assets/                         # собранный JS/CSS
icon.svg / favicon.ico / …      # иконки и site.webmanifest (после build:icons)
private/                        # секреты (закрыты .htaccess):
│  ├─ secrets.example.php       #   шаблон конфигурации
│  ├─ secrets.php               #   ТВОИ логин/пароль/токен (создать, не коммитить)
│  ├─ cache/                    #   серверный кэш ответов VK
│  ├─ asset-cache/              #   gzip-копии ассетов для api.php?action=asset
│  └─ diag/                     #   маячки диагностики загрузчика
scripts/make-hash.php           # генерация хэша пароля
scripts/make-icons.sh           # генерация иконок (rsvg-convert + ImageMagick)
web/                            # React + Vite (исходники)
│  ├─ src/api/                  # client (api.php), config (pageSize)
│  ├─ src/components/           # Login, Gallery, PhotoCard, Pagination, Lightbox
│  ├─ src/hooks/usePhotos.ts    # пагинация + кэш localStorage
│  ├─ icons/icon.svg            # исходная SVG-иконка «В»
│  ├─ shell-runtime.js          # загрузчик ресурсов (встраивается в index.html)
│  └─ shell-config.js           # шаблон списка зеркал/прокси
server/                         # опциональный Node-бэкенд (для будущих этапов ИИ)
```

## Скрипты
